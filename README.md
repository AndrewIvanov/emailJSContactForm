# На связи — статический сайт на Nginx в Docker

**Автор:** Иванов Андрей Александрович, группа 5-МВ-5.

Учебный проект: форма обратной связи на HTML, CSS и JavaScript работает в контейнере Nginx. Docker Compose собирает образ и открывает сайт по адресу <http://localhost:8080>. Папка `public/` подключена с компьютера, поэтому правки сайта видны после обновления страницы без пересборки контейнера.

## Запуск для сдачи ДЗ

1. Установите и запустите Docker Desktop. На Windows выберите Linux containers и WSL 2; на macOS достаточно запустить приложение Docker.
2. Откройте терминал **в папке с `compose.yaml`** и выполните:

   ```bash
   docker version
   docker compose version
   docker compose up --build -d
   docker compose ps
   ```

3. Откройте <http://localhost:8080>. Для запуска сайта через Docker Node.js и `npm install` не нужны. При первой сборке нужен интернет для загрузки `nginx:alpine`.

### Проверка обновления без пересборки

В `public/index.html` найдите текст `Мы будем рады вашему сообщению.` и временно замените его на `Привет из Nginx в Docker!`. Сохраните файл и обновите страницу. Новый текст появится без `docker compose restart` или повторной сборки. После демонстрации можно вернуть исходный текст.

### Управление контейнером

| Команда | Назначение |
| --- | --- |
| `docker compose ps` | Состояние контейнера и проброс порта |
| `docker compose logs -f web` | Логи Nginx; Ctrl+C завершает просмотр логов |
| `docker compose exec web nginx -t` | Проверка конфигурации Nginx |
| `docker compose restart web` | Перезапуск после изменения `nginx.conf` |
| `docker compose down` | Остановка и удаление контейнера и сети проекта |

Если порт 8080 занят, создайте файл `.env` рядом с `compose.yaml`, впишите строку `SITE_PORT=18080` и снова выполните `docker compose up -d`. Сайт будет доступен по адресу <http://localhost:18080>. Образец настроек находится в `.env.example`. Без `.env` используется порт 8080.

На компьютере, где подготовлен проект, порт 8080 уже занят: в локальном `.env` выбран **18080**. Этот файл не входит в Git и архив для сдачи.

Если Docker Hub возвращает `TLS handshake timeout`, повторите запуск при доступном соединении с Docker Hub. Для этой машины образ удалось загрузить из [кэширующего зеркала Google](https://cloud.google.com/artifact-registry/docs/pull-cached-dockerhub-images):

```bash
docker pull mirror.gcr.io/library/nginx:alpine
docker tag mirror.gcr.io/library/nginx:alpine nginx:alpine
docker compose up --build -d
```

Глобальные настройки Docker при этом менять не требуется.

## Исходный проект и другие способы запуска

Адаптивная страница на HTML, CSS и JavaScript для Firebase Hosting. Собственный сервер и сборка не нужны. EmailJS SDK 4.4.1 включён в проект локально; внешний сервис вызывается только при отправке формы. Шрифты загружаются из Google Fonts, при их недоступности используются системные.

**Сейчас почта не подключена.** Без настроек форма проверяет поля, но не отправляет письма и не показывает ложное сообщение об успехе.

## Запуск

Нужен Node.js 20 или новее. Устанавливать зависимости для локального запуска не требуется.

```bash
npm start
```

Откройте <http://127.0.0.1:5173>. Если порт занят: `PORT=5174 npm start`.

Проверка синтаксиса:

```bash
npm run check
```

## Подключение EmailJS

1. Зарегистрируйтесь в [EmailJS](https://dashboard.emailjs.com/sign-up). В **Email Services → Add New Service** подключите почту, с которой будут отправляться письма. Скопируйте **Service ID**.
2. В **Email Templates → Create New Template** создайте шаблон. В **To Email** укажите свой адрес получателя. В **From Name** — `{{user_name}}`, в **Reply To** — `{{user_email}}`. **From Email** оставьте адресом подключённого сервиса. Тема может быть `Новое сообщение от {{user_name}}`.
3. Вставьте в тело письма:

   ```text
   Имя: {{user_name}}
   Email: {{user_email}}

   Сообщение:
   {{message}}
   ```

   Сохраните шаблон и скопируйте **Template ID**. Не используйте тройные фигурные скобки: обычные `{{...}}` экранируют HTML из пользовательского ввода.
4. В настройках аккаунта скопируйте **Public Key**. Заполните `public/config.js`:

   ```js
   export const EMAILJS_CONFIG = Object.freeze({
     publicKey: 'ваш публичный ключ',
     serviceId: 'service_ваш_id',
     templateId: 'template_ваш_id',
   });
   ```

5. В настройках безопасности EmailJS добавьте разрешённые источники: `http://localhost:8080` для Docker, `http://127.0.0.1:5173` для Node.js, `https://ВАШ_PROJECT_ID.web.app` и `https://ВАШ_PROJECT_ID.firebaseapp.com` для Firebase, а также свой домен, если он есть. Если меняли порт Docker, укажите источник с новым портом.
6. Перезагрузите страницу и отправьте пробное сообщение. Проверьте получателя, папку «Спам» и историю отправок EmailJS. При нажатии «Ответить» должен подставляться адрес из формы.

Public Key доступен посетителям — это предусмотрено EmailJS. Private Key, пароль от почты и SMTP-пароль в файлы сайта добавлять нельзя. Адрес получателя задаётся в шаблоне EmailJS, а не посетителем формы.

## Публикация на Firebase Hosting

1. Создайте проект в [Firebase Console](https://console.firebase.google.com/) и запишите его Project ID.
2. Если Firebase CLI ещё не установлен:

   ```bash
   npm install -g firebase-tools
   ```

3. Авторизуйтесь и опубликуйте сайт из корня этого проекта, заменив `ВАШ_PROJECT_ID`:

   ```bash
   firebase login
   firebase deploy --only hosting --project ВАШ_PROJECT_ID
   ```

   `firebase.json` уже настроен на папку `public`. Запускать `firebase init` и перезаписывать готовую страницу не нужно.

4. CLI выведет адрес сайта. Добавьте его в список разрешённых источников EmailJS, если ещё не добавили.

При желании сохраните проект через `firebase use --add`, затем публикуйте командой `npm run deploy`. Локальный файл `.firebaserc` исключён из Git, чтобы случайно не выбрать чужой проект.

## Поведение формы

- Поля `user_name`, `user_email`, `message` совпадают с переменными шаблона. Пробелы по краям удаляются; пустые поля и некорректный email не отправляются.
- Во время запроса кнопка блокируется, поля доступны только для чтения. Повторная отправка ограничена интервалом 10 секунд в SDK; это дополнение к ограничениям сервиса, а не серверная защита от спама.
- После успешного ответа EmailJS форма очищается. При ошибке данные сохраняются в полях, чтобы можно было повторить попытку.
- Скрытое поле ловит простейших ботов. Для публичного сайта настройте ограничения доменов и следите за квотой в EmailJS. Если включите reCAPTCHA в шаблоне, понадобится отдельно добавить виджет и разрешения CSP: в текущей форме капча не подключена.
- Поля имеют подписи и связанные сообщения об ошибках; результат отправки объявляется программам чтения с экрана. Диалог о данных закрывается кнопкой, Escape и нажатием вне окна.
- Эта страница не сохраняет текст в localStorage, cookies или базе данных. EmailJS и почтовый сервис обрабатывают переданные сообщения.
